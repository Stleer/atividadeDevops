# Portal Acadêmico DevOps

Projeto evoluído na atividade prática de colaboração com Git e GitHub — Versão 1.1

Evoluir o Portal Acadêmico DevOps com base na demanda do cliente externo, tornando-o uma verdadeira porta de entrada acadêmica que oriente o aluno sobre o que fazer primeiro.

## 📝 Principais Mudanças (Rodada 1)

### Estrutura (HTML)
- Adicionado badge "Período Letivo 2026.2" no cabeçalho para identidade visual
- Inserido subtítulo orientando o aluno novo a começar pela Matrícula
- Adicionadas etiquetas de etapa ("1º passo", "2º passo", "3º passo") nos cards de serviço
- Criada nova seção "Horário de Atendimento" com prazos de resposta
- Adicionado campo de e-mail no formulário de contato
- Inserido rodapé com informações do projeto

### Interface (CSS)
- Implementado efeito hover no botão "Ver serviços" (elevação + sombra)
- Melhorado contraste e espaçamento dos cards na versão mobile
- Adicionados estados hover nos cards com elevação e sombra
- Destaque visual no card de Matrícula (1º passo) com cor diferenciada
- Estilização da nova seção de horário de atendimento
- Animações suaves de transição em botões e cards
- Campo de entrada com feedback visual de foco e validação

### Funcionalidades (JavaScript)
- Validação de campos obrigatórios no formulário (nome, e-mail, mensagem)
- Validação de formato de e-mail
- Validação de tamanho mínimo da mensagem (10 caracteres)
- Confirmação visual clara após envio (mensagem de sucesso estilizada)
- Exibição de mensagens de erro específicas para cada tipo de validação
- Limpeza automática do formulário após envio bem-sucedido

## 🔄 Fluxo de Trabalho Adotado

1. **Organização:** Criação do repositório, primeiro commit e publicação inicial no GitHub Pages
2. **Entrevista com cliente externo:** Levantamento de demandas e prioridades
3. **Issue principal:** Registro formal da demanda "Evolução do Portal Acadêmico DevOps - versão 1.1" com 8 requisitos
4. **Planejamento interno:** Distribuição de tarefas por papéis e criação de branches (`feature/interface`, `feature/funcionalidades`, `README-1.1`)
5. **Desenvolvimento paralelo:** Cada integrante trabalhou em sua branch com commits descritivos
6. **Pull Requests:** Abertura de PRs explicando requisitos atendidos, arquivos alterados e decisões tomadas
7. **Revisão cruzada:** Comentários de aprovação e ajuste nos Pull Requests
8. **Integração:** Merge na branch `main` após aprovação
